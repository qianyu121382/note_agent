# 消息传递通信协议 (MCP) 概述

消息传递通信协议 (MCP) 是一种基础架构范式，用于构建和协调自主或半自主计算实体之间的交互，尤其适用于分布式或多智能体系统。MCP 的核心在于通过交换明确定义的、自包含的数据结构（即“消息”）来实现组件间的通信，而非直接调用方法或共享内存进行交互。

## MCP 的核心原则

MCP 系统的有效性和稳健性源于基本原则：

1. **状态封装和信息隐藏**
   - 每个智能体被视为‘黑箱’，维护其内部状态，其他智能体无法直接访问。
   - 唯一的影响或查询智能体状态的方式是通过明确定义的接口进行消息进出，避免了共享状态模型中的复杂并发问题。

2. **异步通信**
   - 发送者无需等待响应，可以继续执行其他任务。
   - 这种非阻塞特性对高吞吐量系统至关重要，允许智能体并行操作。

3. **消息作为一等公民**
   - 在 MCP 范式中，消息不仅是信号，而是结构化的数据工件。
   - 消息封装有效载荷（核心数据）及丰富的元数据（如路由信息、发送者/接收者标识符、时间戳和关联 ID），对编排、调试和可观察性至关重要。

## 典型消息的结构

典型消息通常具有以下多部分结构：

- **头部**
  - 包含通信基础设施的元数据，常见字段包括：
    - `message_id`：消息的唯一标识符。
    - `sender_id`：发起智能体的唯一标识符。
    - `recipient_id`：预期接收者的地址或主题。
    - `timestamp`：消息创建的 UTC 时间戳。
    - `correlation_id`：用于将响应消息与请求消息链接的标识符。

- **主体（有效载荷）**
  - 消息的实质内容，包含应用特定数据，通常序列化为标准格式（如 JSON、XML 或 Protocol Buffers）。

- **属性/元数据**
  - 可扩展的键值集合，携带辅助的应用级或框架级信息，如安全令牌、优先级级别或特殊处理的标志。

## 现代智能体框架中的概念同构

现代多智能体系统框架（如 LangGraph）体现 MCP 范式。

- **`State` 对象**（如 `AgentState`）可视为 **消息** 本身，作为结构化工件在不同处理单元之间传递。
- 图中的每个 **`Node`** 充当一个 **智能体**，接收状态对象（消息），执行特定转换或计算，并将修改后的状态对象作为输出发出。
- 图的 **`Edges`** 代表 **通信通道** 或消息总线的路由逻辑，决定哪个智能体（节点）将接收下一条消息。

这种架构确保数据流明确且可追踪，每个功能单元（节点）与其同伴保持高度内聚和松耦合，从而维护消息传递通信协议的核心原则。
