# 笔记状态如何管理

本文档说明 `note_agent` 项目中“笔记状态”是如何被管理的、包含哪些核心属性，以及这些逻辑在代码里的位置。

## 1. 什么是笔记状态

笔记状态指的是：

> 某一篇笔记对象本身的结构化状态。

它描述的是“这篇笔记是什么”，而不是“当前会话正在做什么”。

例如：
- 这篇笔记的唯一标识是什么
- 标题是什么
- 正文保存在哪里
- 来源是什么
- 当前是第几版
- 是否已经完成 RAG 索引

这些都属于笔记状态。

## 2. 当前项目中的笔记管理方式

当前项目采用的是“正文 + 元数据 + 总索引”的管理方式。

### 2.1 正文存储
笔记正文保存为 Markdown 文件。

存储目录：
- `backend/data/notes/`

作用：
- 保存用户真正要查看和编辑的笔记正文
- 这是笔记内容的主数据源（source of truth）

### 2.2 元数据存储
每篇笔记对应一份 JSON 元数据。

存储目录：
- `backend/data/notes_meta/`

作用：
- 保存这篇笔记的结构化属性
- 便于后续做修改、列表、检索、版本管理

### 2.3 总索引存储
项目还维护了一份总索引文件。

存储文件：
- `backend/data/notes_index.json`

作用：
- 快速列出已有笔记
- 作为笔记列表页和后续检索入口的轻量索引

## 3. 笔记状态的核心属性

当前项目里的笔记状态主要围绕 `NoteMetadata` 设计。

### 3.1 `note_id`
- 类型：`str`
- 含义：笔记唯一标识
- 作用：修改、读取、会话绑定、后续 RAG 建索引都依赖它

### 3.2 `title`
- 类型：`str`
- 含义：笔记标题
- 作用：面向用户展示，也影响文件命名

### 3.3 `filename`
- 类型：`str`
- 含义：正文 Markdown 文件名
- 作用：把笔记对象和本地 Markdown 文件关联起来

### 3.4 `summary`
- 类型：`str`
- 含义：笔记摘要
- 作用：用于列表展示、检索预览、后续摘要能力

### 3.5 `tags`
- 类型：`list[str]`
- 含义：笔记标签
- 作用：后续分类、筛选、检索

### 3.6 `source_type`
- 类型：`str`
- 含义：笔记主要来源类型
- 常见值：
  - `url`
  - `text`
  - `file_path`
  - `mixed`

### 3.7 `source_ref`
- 类型：`str`
- 含义：主要来源引用
- 可能内容：
  - 某个 URL
  - 本地文件路径
  - 来源描述

### 3.8 `source_refs`
- 类型：`list`
- 含义：多来源引用列表
- 作用：为后续多资料整理做准备

### 3.9 `thread_id`
- 类型：`str | None`
- 含义：创建这篇笔记时关联的原始会话来源
- 作用：帮助回溯这篇笔记最初来自哪个 thread

注意：
- 这个字段只是记录来源关系
- 当前正在编辑哪篇笔记，属于会话状态，不属于笔记状态

### 3.10 `status`
- 类型：`str`
- 含义：笔记当前状态
- 建议值：
  - `active`
  - `archived`

### 3.11 `version`
- 类型：`int`
- 含义：笔记当前版本号
- 作用：每次更新时递增，用于版本管理

### 3.12 `created_at`
- 类型：`str`
- 含义：创建时间
- 作用：用于排序和审计

### 3.13 `updated_at`
- 类型：`str`
- 含义：最近更新时间
- 作用：用于最近修改排序和展示

### 3.14 `last_modified_from`
- 类型：`str`
- 含义：最近一次修改来源
- 常见值：
  - `create`
  - `edit`
  - `rewrite`
  - `rag_update`

### 3.15 `rag_indexed`
- 类型：`bool`
- 含义：是否已完成向量化索引
- 作用：后续做 RAG 时判断是否需要重新入库

## 4. 一个典型的笔记状态示例

```json
{
  "note_id": "note_ab12cd34ef56",
  "title": "LangGraph 学习笔记",
  "filename": "note_ab12cd34ef56_LangGraph.md",
  "summary": "关于 LangGraph、ReAct 和多轮 Agent 设计的整理笔记",
  "tags": ["langgraph", "agent", "react"],
  "source_type": "url",
  "source_ref": "https://example.com/langgraph-guide",
  "source_refs": [],
```

## 5. 笔记状态相关代码位置

### 5.1 笔记状态模型与存储逻辑
文件：
- `backend/src/agent/tools/note_store.py`

这里负责：
- 定义 `SourceRef`
- 定义 `NoteMetadata`
- 定义 `NoteRecord`
- 创建笔记 `create_note`
- 读取笔记 `get_note`
- 更新笔记 `update_note`
- 列出笔记 `list_notes`
- 写入 `notes/`、`notes_meta/`、`notes_index.json`

这是当前项目里“笔记状态管理”的核心文件。

### 5.2 LLM 可调用的笔记工具
文件：
- `backend/src/agent/tools/local_tools.py`

这里负责把底层笔记存储逻辑包装成 LLM 可调用工具，例如：
- `create_note_record`
- `read_note`
- `update_note_record`
- `list_note_records`

也就是说：
- `note_store.py` 管底层状态和存储
- `local_tools.py` 管 Agent 如何调用这些能力

### 5.3 工具注册入口
文件：
- `backend/src/agent/tools/__init__.py`

这里负责把本地笔记工具和其它工具一起聚合到 `all_tools` 中，供 ReAct Agent 使用。

### 5.4 ReAct Agent 使用这些笔记工具的入口
文件：
- `backend/src/agent/react_agent/graph.py`
- `backend/src/agent/react_agent/prompts/system.txt`

这里负责：
- 把所有工具绑定到模型
- 指导模型在创建笔记时调用 `create_note_record`
- 在修改笔记时调用 `read_note`、`update_note_record`

### 5.5 当前活动笔记与会话绑定逻辑
文件：
- `backend/src/agent/graph.py`
- `backend/src/agent/state.py`

这里不是在管理“笔记对象本身”，而是在管理：
- 当前会话正在处理哪篇笔记
- 如何从工具结果里解析 `active_note_id`

这属于“会话状态与笔记状态的连接层”。

## 6. 为什么要单独管理笔记状态

如果没有明确的笔记状态，系统只能把笔记当成“一个普通 Markdown 文件”。

这样会导致这些能力很难做稳：
- 修改刚才那篇笔记
- 为一篇笔记维护版本号
- 为笔记做 RAG 索引
- 展示笔记列表
- 根据来源回溯笔记生成过程

所以笔记状态的意义是：

> 把笔记从“一个文件”升级成“一个可管理的对象”。

## 7. 一句话总结

在 `note_agent` 中，笔记状态由 `NoteMetadata` 和笔记正文共同组成：
- Markdown 正文存储在 `backend/data/notes/`
- 元数据存储在 `backend/data/notes_meta/`
- 总索引存储在 `backend/data/notes_index.json`

核心代码集中在：
- `backend/src/agent/tools/note_store.py`
- `backend/src/agent/tools/local_tools.py`

它们共同构成了当前项目中“笔记状态管理”的基础能力。
