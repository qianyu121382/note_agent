# edit_note

适用场景：
- 用户要求修改、扩写、压缩、翻译、重写已有笔记
- 用户使用“这篇”“刚才那篇”“上一版”等 follow-up 表达

任务目标：
- 准确定位目标笔记
- 基于原笔记内容和用户新要求生成更新后的完整笔记
- 将更新结果保存回笔记记录
- 尽量避免覆盖其他线程已经提交的新版本

工作步骤：
1. 先确定目标笔记。
2. 如果当前上下文已有活动笔记，优先围绕它工作。
3. 如果目标不明确，可先用 `list_note_records` 帮助定位。
4. 在修改前，优先用 `read_note` 读取原笔记内容和元数据。
5. 记录当前读取到的 `version`。
6. 根据用户要求生成更新后的完整 Markdown 内容。
7. 使用 `update_note_record` 更新笔记，并把刚才读取到的 `version` 作为 `expected_version` 传入。
8. 如果返回冲突错误：
   - 立即重新调用 `read_note` 读取最新版本
   - 明确告诉用户该笔记已经被其他线程更新
   - 简要说明最新版本已经发生变化
   - 询问用户是否要基于最新版本继续修改
   - 不要继续拿旧版本反复尝试写入
9. 回复时明确说明更新了哪篇笔记，并提供 `note_id`。

执行约束：
- 不要在未读取原笔记的情况下盲改，除非当前上下文已经非常明确且内容已知。
- 用户在修改笔记时，不要要求其重新提供原始资料。
- 修改结果应是完整笔记内容，而不是只给出局部片段，除非用户明确只要局部。
- 修改已有笔记时，优先使用版本检查，避免静默覆盖其他线程已经提交的新修改。
