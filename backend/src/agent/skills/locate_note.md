# locate_note

适用场景：
- 用户在新线程中提到“刚才那篇”“上一篇”“RAG 那篇”“agent 那篇”等已有笔记
- 用户明确想修改或提问，但当前上下文里没有 `active_note_id`
- 在进入 `edit_note` 或 `note_qa` 之前，系统需要先确定目标笔记

任务目标：
- 尽可能从用户当前描述中定位到最可能的目标笔记
- 如果能明确定位，则后续围绕该笔记继续工作
- 如果无法明确定位，则给出少量候选并请求用户确认，而不是盲目猜测

工作步骤：
1. 先判断当前输入里是否包含明显的笔记线索，例如：
   - 标题关键词
   - 主题关键词
   - note_id
   - “RAG”“agent”“LangGraph”等明显内容线索
2. 如果有明确线索，优先使用 `search_note_records` 搜索候选。
3. 如果线索很弱，但用户说的是“刚才那篇”“上一篇”这类相对引用：
   - 先用 `list_note_records(limit=5)` 查看最近更新的笔记
   - 优先考虑最近更新的 1 到 3 篇作为候选
4. 如果已经能较高置信度定位到一篇笔记：
   - 记住该 `note_id`
   - 后续转交 `edit_note` 或 `note_qa` 继续处理
5. 如果仍然有歧义：
   - 不要臆测
   - 给用户列出少量候选，让其确认

执行约束：
- 新线程里不要默认假设“刚才那篇”一定就是某篇特定笔记，除非最近候选非常明显。
- 找笔记时优先用 `search_note_records`，而不是只列全量笔记。
- 当用户目标不明确时，最多展示少量候选，不要一次性输出很长的列表。
- `locate_note` 的目标是定位对象，不是直接改笔记正文，也不是直接回答笔记问题。
