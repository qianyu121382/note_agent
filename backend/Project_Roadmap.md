# 智能笔记 Agent 项目优化路线图

本文档旨在为智能笔记 Agent 项目的后续开发提供一个清晰、分阶段、有优先级的路线图。通过遵循此路线图，我们可以确保项目在稳固的基础上逐步迭代，系统性地增强功能和用户体验。

---

## 第一优先级 (Tier 1): 项目的生存基础 (Bedrock: Stability & Persistence)

此阶段的目标是确保项目具备最基本的核心能力：**能用、不死、数据不丢**。这是后续所有功能开发的基石。

### 1. 持久化 (#6)

**目标**: 确保所有用户数据和 Agent 状态都能被可靠地保存。

*   **核心任务**:
    *   实现笔记的可靠本地存储，例如，将生成的笔记以 Markdown 格式保存到指定目录。
    *   如果 Agent 具有跨会话的状态（例如，当前处理的文件列表），也需要设计机制进行持久化。
*   **验收标准**: 关闭并重启程序后，之前创建的笔记和相关状态完好无损。

### 2. 全局错误处理 (#1)

**目标**: 提升应用的健壮性，防止因意外错误（如网络问题、API 限制）导致程序崩溃。

*   **核心任务**:
    *   在所有关键路径（特别是外部 I/O、API 调用、文件读写等）上，全面实施 `try...except` 错误捕获机制。
    *   建立简单的日志系统（Logging），记录关键操作和错误信息，便于调试。
    *   为用户提供友好的错误提示，而不是直接暴露堆栈信息。
*   **验收标准**: 在模拟的网络失败或 API 异常情况下，程序能够捕获错误、提示用户，并保持运行状态。

---

## 第二优先级 (Tier 2): 核心功能的健壮性 (Core Engine: Robustness & Intelligence)

在项目稳定运行的基础上，此阶段专注于**提升核心功能在真实场景下的可靠性**，并开始注入初步的“智能”。

### 3. LLM 上下文长度问题 (#2)

**目标**: 解决因输入内容过长导致的 LLM 上下文窗口溢出问题，这是核心笔记功能的关键瓶颈。

*   **核心任务**:
    *   实现稳健的文本分块（Chunking）策略，确保任何长度的文档都能被安全、有效地处理。
    *   可以考虑实现对话历史的摘要机制，作为管理长对话上下文的解决方案。
*   **验收标准**: Agent 能够成功处理远超 LLM 单次上下文限制的长文档，并生成完整的笔记。

### 4. 用户记忆偏好 (#7)

**目标**: 赋予 Agent 学习和记忆用户偏好的能力，实现个性化服务，这是项目从“工具”迈向“智能助手”的关键一步。

*   **核心任务**:
    *   设计并实现“识别 -> 存储 -> 应用”的记忆流水线。
    *   **识别**: 通过 LLM 的“反思”能力，从对话中提取用户的偏好信息。
    *   **存储**: 采用结构化（如 SQLite, JSON 文件）与非结构化（向量数据库）结合的方式存储偏好。
    *   **应用**: 在执行相关任务（如生成笔记）前，自动检索并应用这些偏好。
*   **验收标准**: Agent 能够根据用户之前表达的偏好（如“不喜欢代码多的笔记”），调整其后续的行为和产出。

---

## 第三优先级 (Tier 3): 功能扩展与用户体验 (Feature Expansion & UX)

当 Agent 拥有了稳定、可靠且具备初步智能的核心后，我们可以开始横向扩展其能力，并优化用户与它交互的体验。

### 5. 应对更灵活的需求 (如修改笔记) (#3)

**目标**: 扩展 Agent 的能力范围，使其能处理更多样的用户指令。

*   **核心任务**:
    *   设计和实现一个意图识别/路由模块，用于判断用户的指令是“新增”、“修改”还是“查询”笔记。
    *   为 Agent 开发新的“工具 (Tools)”，例如 `modify_note(note_id, new_content)`。
*   **验收标准**: 用户可以通过自然语言指令，让 Agent 修改一篇已经存在的笔记。

### 6. 前端可视化 (#5)

**目标**: 优化用户界面，让 Agent 的功能和价值能被更直观地感知。

*   **核心任务**:
    *   改进笔记的渲染和展示效果。
    *   提供更流畅的人机交互界面。
    *   （可选）将 Agent 的思考过程（Chain of Thought）或当前状态进行可视化展示。
*   **验收标准**: 用户能够通过一个美观、易用的界面与 Agent 进行所有核心功能的交互。

---

## 第四优先级 (Tier 4): 深度优化与前沿探索 (Advanced R&D)

在功能完备、体验良好的基础上，此阶段专注于对底层技术进行深度优化，追求更高的性能和效果，展示项目的技术深度。

### 7. 更复杂的 RAG (#4)

**目标**: 提升 Agent 记忆系统（去重、问答）的检索精度和效率。

*   **核心任务**:
    *   在当前 RAG 实现的基础上，引入 Reranker 模型进行二次精排，提升检索精度。
    *   或者，探索并实现像 ColBERT 这样端到端的、在性能和效果上取得更优平衡的先进检索模型。
    *   研究 RAPTOR 等树状检索方法，为未来实现知识的“多粒度理解”打下基础。
*   **验收标准**: 通过评估框架（如 RAGAs）量化证明，新方案在检索精度、召回率等指标上相比旧方案有显著提升。
